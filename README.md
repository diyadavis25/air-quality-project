# Air Quality Prediction & Pollution Pattern Analysis

College Data Analytics micro-project (Python, pandas, scikit-learn, Plotly, Streamlit).

> **Status: Part 2 of 2 – complete.** Part 1: data pipeline, EDA, pollution pattern analysis, ML training/evaluation,
> prediction, Streamlit dashboard, tests. Part 2: the `docs/` folder (project report, viva questions, presentation
> outline, methodology) and `src/results_summary.py`, which generates the Results numbers from your real run.
> The Results section below and the ⟨RESULT⟩ markers in `docs/` are filled by **you** after running on the real dataset
> (no results are invented in this repository).

## Objectives
- **A. Pollution pattern analysis** – daily/monthly/yearly/seasonal trends, city comparison, hotspots, pollutant correlations.
- **B. AQI prediction** – Linear Regression vs Random Forest (+ mean baseline) estimating AQI from pollutant readings.
  This is *estimation from same-day pollutants*, **not** future forecasting (no time-series model is implemented).

## Inputs
**Input 1 – historical CSV (analysis + training):** Date, City, PM2.5, PM10, NO₂, SO₂, CO, O₃, AQI.
Output: trends, city comparison, correlation heatmaps, trained model.
**Input 2 – new pollutant values (prediction form):** PM2.5, PM10, NO₂, SO₂, CO, O₃ entered manually, in the units of the
training dataset (CO is dataset-specific). Output: predicted AQI + CPCB category. Values may come from manual entry, the
CSV, or (future work) an air-quality API/sensors. Blank fields are filled with the training median and flagged.
Only these six pollutants are used; other CSV columns are ignored. Changing the pollutant set requires **retraining**
(`python -m src.model_training`); an old model trained on other features is rejected automatically.

## Dataset
Kaggle: <https://www.kaggle.com/datasets/rohanrao/air-quality-data-in-india> → use `city_day.csv`.
Copy it to `data/air_quality.csv` (see `data/README.md`). The presentation's figures (~29,500 rows, 26 cities, 2015–2020)
must be verified: the *Dataset Explorer* page shows the real counts.

## Methodology (key decisions)
- **Cleaning:** drop invalid dates and duplicate (City, Date); negative concentrations → NaN; rows with missing AQI are
  **dropped, never imputed or recomputed**; outliers are flagged (IQR), not removed (real smog episodes are genuine).
- **AQI categories:** CPCB bands 0–50 Good, 51–100 Satisfactory, 101–200 Moderate, 201–300 Poor, 301–400 Very Poor, 401+ Severe.
- **Features:** the six pollutants (PM2.5, PM10, NO2, SO2, CO, O3) with ≥50% coverage. `AQI_Bucket` excluded (derived from the target → leakage). Date/City not used.
- **Split:** chronological 70/15/15. Model chosen by **validation RMSE**; test set reported once. Median imputation + scaling
  are inside a sklearn `Pipeline` (fit on training data only). Seed 42. Saved with joblib.
- **Metrics:** MAE, MSE, RMSE, R². Actual-vs-predicted and residual plots on the Model Performance page.

## Limitations
Estimates AQI from same-day pollutant values only; inputs far outside the training range are unreliable; cities have
different date coverage; correlation ≠ causation; output is not an official AQI.

## Troubleshooting
- *"Dataset not found"* → place the CSV as described above.
- *"No trained model found"* → run `python -m src.model_training`.
- Missing columns → the loader reports which; column names are matched case-insensitively (PM2.5/pm25 etc.).
